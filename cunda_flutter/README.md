# cunda_flutter

Flutter mobile app that communicates with the ESP32 firmware over BLE. Uses
[flutter_rust_bridge](https://github.com/fzyzcjy/flutter_rust_bridge) to
call into a Rust native library that handles all RPC serialization, and
[flutter_blue_plus](https://pub.dev/packages/flutter_blue_plus) for BLE
transport. State management is done with [Riverpod](https://riverpod.dev/).

## Build

```bash
# From repo root (includes codegen):
just run-flutter

# Skip codegen (faster iteration):
just run-flutter-fast

# Codegen only (run after protocol changes):
just codegen-flutter
```

Codegen has two steps and both are required after any change to the `protocol` or `frb_prpc_juggle` crates:
1. `flutter_rust_bridge_codegen generate` — generates Dart bindings from the Rust native library.
2. `dart run build_runner build` — generates `.g.dart` files for Riverpod annotations.

## Structure

```
lib/
  main.dart                        App entry point, Riverpod scope, logging setup
  constants.dart                   App-wide constants

  services/ble/
    ble.dart                       BleAdapter / BleScanner / BleService abstracts
    ble_fbp_impl.dart              Real implementation using flutter_blue_plus
    ble_fake_impl.dart             Fake implementation for testing/UI dev

  providers/
    ble/ble_providers.dart         BLE adapter, scanner, and connection manager providers
    rpc/client.dart                rpcClient provider — discovers GATT service, wires TX/RX streams to Rust Client
    rpc/protocol.dart              Typed Riverpod providers for each RPC call / topic subscription

  pages/
    scanner/scanner.dart           Scan for and connect to BLE devices
    device/device.dart             Main device screen (3-tab layout)
    device/device_view_model.dart  ViewModel for the device screen
    device/tab_0_application_page.dart   Application settings tab
    device/tab_1_system_page.dart        System stats tab (CPU, memory, uptime)
    device/tab_2_settings_page.dart      System settings tab (BLE device name, etc.)
    device/ota_section.dart              OTA firmware update UI
    device/application_settings_section.dart
    device/systems_settings_section.dart

  frb_generated/                   Auto-generated by flutter_rust_bridge_codegen — do not edit

rust_lib_cunda_flutter/          The rust code that is compiled after flutter_rust_bridge_codegen
```

## How the RPC client works

`providers/rpc/client.dart` (`rpcClient` provider) connects the two transports:

1. **Flutter → Rust (TX):** `client.init()` returns a `Stream<Uint8List>`. The provider subscribes to it and writes each chunk to the `toServer` BLE characteristic. Chunks are sized to `MTU - 3` bytes.

2. **Rust → Flutter (RX):** BLE Indications arriving on the `toClient` characteristic call `client.rxCallback(data)`. The Rust side deframes COBS, routes responses to waiting endpoint futures, and dispatches topic messages to registered `StreamSink`s.

3. On connection, `approveFirmware` is called automatically so the OTA bootloader marks the running image as valid.
